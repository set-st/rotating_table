# CLAUDE.md — база знань проєкту

Цей файл автоматично завантажується Claude Code у кожній сесії на будь-якому
комп'ютері (розробка ведеться на macOS і Linux). Сюди записуються рішення,
домовленості та неочевидні факти про проєкт. Оновлюйте його разом із кодом.

## Мова та стиль

- Коментарі в коді, повідомлення API/Serial, веб-інтерфейс і документація —
  **українською**. Користувач спілкується російською.
- **Коміти та push робить користувач сам** — не комітити й не пропонувати коміт;
  після змін лише коротко перелічити змінені файли.
- Детальна документація: `README.md` (поворотний стіл + нахил), `RAILWAY.md`
  (RailWay). Цей файл — стисла довідка та журнал рішень, не дублюйте README.

## Структура: три окремі прошивки ESP32 (PlatformIO, Arduino, espressif32@7.1.3)

| Env | Плата | Точка входу | Файли |
|---|---|---|---|
| `rotating_table` | ESP32 master | `src/main.cpp` | `motion_controller`, `web_server` + `web_ui.h`, `imu_sensor`, `table_ble_client`, `wifi_manager`, `ota_updater`, `config.h` |
| `tilt_platform` | ESP32 slave | `src/main_tilt.cpp` | `tilt_*` (`tilt_protocol.h` — спільний BLE-протокол з master) |
| `railway` | MKS DLC32 V2.2 | `src/main_railway.cpp` | `railway_*`, спільні `wifi_manager`, `ota_updater` |

- Розподіл файлів між прошивками — через `build_src_filter` у `platformio.ini`.
  Новий файл з префіксом `tilt_`/`railway_` автоматично потрапляє лише у свою ціль.
- master ↔ tilt: BLE (NimBLE). RailWay — повністю незалежний, **без BLE**.
- Налаштування всіх плат зберігаються в NVS (`Preferences`); RailWay — namespace `railway`.
- Веб-інтерфейси вбудовані як рядки в `include/web_ui.h` і `include/railway_ui.h`.

## Команди

```bash
pio run                      # зібрати всі три прошивки
pio run -e railway           # одна прошивка
pio run -e railway -t upload # прошити через USB
pio device monitor           # Serial 115200
python simulator.py          # симулятор поворотного столу: http://127.0.0.1:8080
python railway_simulator.py  # симулятор RailWay:           http://127.0.0.1:8081
```

- Після змін у прошивці щонайменше перевіряти збірку відповідного env.
- Симулятори відтворюють API; при зміні API/UI оновлювати й симулятор.
- CI (`.github/workflows/compile.yml`) збирає всі env; тег `v*` → GitHub Release
  з `rotating_table.bin`, `tilt_platform.bin`, `railway.bin` (на них спирається OTA).
  Версія підставляється `scripts/inject_version.py` зі змінної `FIRMWARE_VERSION`.
- `compile_commands.json` у репозиторії згенеровано на macOS (абсолютні шляхи);
  на Linux за потреби перегенерувати: `pio run -t compiledb`.

## RailWay: стан і рішення

- Прошивка — чернетка: збирається, **на залізі ще не перевірялась**.
- STEP/DIR/EN — програмний вивід у регістри зсуву DLC32 (BCK 16, WS 17, DATA 21,
  біт N = `I2SO(N)`) з таймера 20 кГц; профіль руху рахує задача FreeRTOS (5 мс).
  Порядок бітів, полярність засувки та рівень EN потрібно перевірити на платі.
- Механіка: двигуни 17HS3401S, TMC2209 (мікрокрок 1/16 DIP), GT2 + шків 20 зуб.
  → 80 кроків/мм (перевірити вимірюванням).
- **Довжина X вимірюється при homing між двома кінцевиками** (фаза `MEASURE`) і
  зберігається в NVS. Задокументовані ~6 м — лише теоретичне значення, у код не
  зашивати. Висоту Z (кінцевик один, зверху) задають вручну.
- `RW_MAX_LENGTH_MM` (8000 мм) — це межа налаштувань і **максимальний хід пошуку**
  кінцевиків, а не очікувана довжина. Поки X не виміряно, `SEEK` шукає на весь
  цей хід; після вимірювання — `1.2 × довжина`. (Рішення від 2026-11-09.)
- Повний пошук на 8000 мм при 20 мм/с триває до ~410 с до таймауту — перші
  запуски проводити під наглядом.
