# Прошивка комплексу поворотного та нахильного столів на ESP32 (PlatformIO)

Проект складається з двох плат **ESP32**, які взаємодіють між собою через **Bluetooth (BLE)**:
1. **Основна плата — Поворотний стіл (Master)**:
   - Керує кроковим двигуном повороту та кінцевиком.
   - Підключається до Wi-Fi та запускає вбудований Web-сервер із адаптивною адмін-панеллю (Web UI) та REST JSON API.
   - Виступає в ролі BLE-клієнта (Central): автоматично підключається до плати нахилу, опитує її стан, транслює команди та зберігає конфігурацію.
2. **Друга плата — Платформа нахилу (Slave / Tilt Platform)**:
   - Керує кроковим двигуном нахилу через драйвер з оптичною розв'язкою (активні рівні **LOW** для STEP, DIR, ENABLE).
   - Обладнана кінцевиком для фіксації крайньої точки нахилу та захисту від механічного пошкодження.
   - Оснащена гіроскопом/акселерометром **GY-521 (MPU-6050)** для вимірювання кута та **активного підтримання положення (closed-loop stabilization)**.
   - Підтримує збереження нульової точки в енергонезалежну Flash-пам'ять (NVS).
   - Керується та налаштовується повністю дистанційно з основної веб-панелі.

Прошивки для обох плат **компілюються окремо** через PlatformIO environments: `rotating_table` та `tilt_platform`.

## Можливості

- **Локальний симулятор інтерфейсу**:
  - Запускається без ESP32 та без прошивки командою `python simulator.py`.
  - Відкриває той самий веб-інтерфейс на `http://127.0.0.1:8080`.
  - Імітує поворот, homing, автоматичний режим, налаштування та показання IMU.
  - OTA у симуляторі навмисно недоступне.
- **Postman API**:
  - Колекція `postman/rotating-table-api.postman_collection.json` містить автоматичні
    тести відповідей для запуску через Collection Runner.
  - Змініть `baseUrl` на адресу ESP32 або `http://127.0.0.1:8080` для симулятора.
- **Налаштування Homing**:
  - Швидкість швидкого підходу, відкату від кінцевика та повторного точного
    підходу змінюються у веб-інтерфейсі й зберігаються в NVS.
- **Обмеження повороту після Homing**:
  - Максимальний кут від нуля в кожен бік задається в адмінці (за замовчуванням
    180°), тож звичайні команди не виходять за межі `−межа…+межа`.
  - В автоматичному режимі напрямок змінюється на кожній межі.

- **Калібрування 0° (Homing)**:
  - Автоматично при вмиканні пристрою (налаштовується).
  - За командою через Web API (`POST /api/home`) або кнопку у веб-інтерфейсі.
  - Поворот столу вліво (проти годинникової стрілки) до упору в кінцевик з двоетапним підходом (швидкий підхід, відкат назад, повільний точний підхід) для ідеальної повторюваності нуля.
- **Кінематика та розрахунок передаточного числа**:
  - Зручне налаштування кількості зубів шестерень прямо у веб-інтерфейсі (наприклад, 20 зубів на валу мотора і 60 зубів на валу столу).
  - Автоматичний розрахунок передаточного числа ($60 / 20 = 3.00$) та кроків на градус на льоту.
  - Налаштування кількості кроків мотора (200 / 400) та мікрокроку драйвера (1..32) зі збереженням у Flash-пам'ять NVS.
- **Кінематика платформи нахилу**:
  - Передатне число також розраховується за зубцями шестерень: 20 зубів на валу двигуна та 60 на валу платформи дають редукцію 3:1.
  - Кількість імпульсів на градус нахилу враховує передатне число, кроки двигуна та мікрокрок драйвера; розрахунок відображається в налаштуваннях плати нахилу.
- **Повна зміна апаратної конфігурації через веб-інтерфейс**:
  - Вибір активного рівня HIGH/LOW для STEP та ENABLE і рівня DIR для додатного напрямку; підходить для налаштування драйверів з оптопарними входами.
  - Перепризначення GPIO пінів ESP32 (STEP, DIR, ENABLE, ENDSTOP).
  - Налаштування кінцевика (інверсія NO/NC, фільтр брязкоту в мс, напрямок калібрування, авто-пошук нуля при увімкненні).
  - Налаштування швидкостей та прискорення.
- **Оновлення стану в реальному часі (Real-time Live Updates)**:
  - Плавне відображення зміни кута у веб-панелі кожні 300 мс прямо під час обертання столу.
  - Розподіл навантаження процесора: генерація імпульсів двигуна винесена на **Core 0**, а веб-сервер на **Core 1** відповідає миттєво без затримок і зависань.
- **IMU GY-87**:
  - Читання `Pitch`, `Roll` та швидкостей обертання з MPU6050.
  - Відображення показань у веб-інтерфейсі через live API `/api/status`.
  - Калібрування bias гіроскопа та збереження нульового положення Pitch/Roll
    через веб-інтерфейс.
  - Налаштування пінів I2C і адрес MPU6050 та BMP180 через веб-інтерфейс.
  - Поточна версія використовує комплементарний фільтр; BMP180 перевіряється та
    відображається лише як стан підключення.
  - Доступне сканування I2C через `GET /api/imu/scan` з виводом адрес у Serial
    та веб-інтерфейсі.
- **Керування поворотом**:
  - Поворот на заданий кут із заданою швидкістю (`°/сек`).
  - Підтримка абсолютного кута (наприклад, перейти в 90.0°) та відносного зсуву (наприклад, повернути ще на +45.0°).
  - Плавний розгін і гальмування з контролем прискорення.
- **Автоматичне обертання**:
  - Повторюваний відносний поворот із заданими кутом, швидкістю та інтервалом.
  - Запуск і зупинка доступні у веб-інтерфейсі та через `POST /api/automatic/start`
    і `POST /api/automatic/stop`.
  - Аварійна кнопка `STOP` також вимикає автоматичний режим.
- **OTA-оновлення**:
  - Основна плата оновлюється з `rotating_table.bin`; плата нахилу отримує
    `tilt_platform.bin` від master через BLE (`POST /api/ota/tilt/update`).
  - Для завантаження релізу основній платі потрібне підключення STA до Wi-Fi з
    Інтернетом, а для оновлення slave додатково потрібне BLE-з'єднання з ним.
  - Після запису master або slave автоматично перезавантажується. Не вимикайте
    живлення жодної плати під час відповідного оновлення.
  - Перехід з v1.0.6 на v2.0.0 не підтримується через OTA: стара таблиця
    розділів має OTA-слоти по 1 310 720 байт, менші за нову прошивку master.
    Один раз прошийте основну плату через USB, щоб записати нову таблицю
    розділів; після цього наступні оновлення master можна виконувати по OTA.
  - GitHub Actions збирає обидва environment при push у `main`; push тегу
    `v*` додатково створює GitHub Release із файлами `rotating_table.bin` і
    `tilt_platform.bin`. Версія обох прошивок встановлюється за тегом.
  - Щоб випустити реліз: `git tag v1.2.0`, потім `git push origin v1.2.0`.
    Існуючий тег можна повторно зібрати через workflow_dispatch, задавши
    `release_tag`; assets у наявному релізі замінюються.
- **Апаратні кнопки**:
  - Кнопки «Вліво», «Вправо» виконують один відносний поворот на заданий кут.
  - Кнопка «STOP» негайно зупиняє двигун.
  - GPIO, інверсія сигналів, швидкість і кут кроку налаштовуються у веб-інтерфейсі та зберігаються в NVS.
- **Висока плавність та надійність**:
  - Генерація імпульсів крокового двигуна винесена в окремий високопріоритетний потік FreeRTOS на Core 1, що усуває ривки під час обробки мережевих HTTP-запитів.
  - Безпечний таймаут пошуку кінцевика (захист від зациклення у разі обриву дроту).
- **Wi-Fi, Точка доступу (AP) та mDNS**:
  - **Налаштування з веб-інтерфейсу**: сканування ефіру 2.4 ГГц в один клік, введення імені (SSID) та пароля домашньої мережі, а також зміна імені власної точки доступу столу (SoftAP) та її пароля.
  - Збереження параметрів у пам'ять NVS ESP32.
  - Автоматичний перехід у режим власної точки доступу `RotatingTable-ESP32` (IP: `192.168.4.1`) у разі недоступності роутера.
  - Доступ за локальним мережевим ім'ям: `http://rotating-table.local`.
- **Вбудована веб-панель**:
  - Стильний компактний інтерфейс у стилі dark-mode з підтримкою смартфонів та ПК.
  - Згортані секції налаштувань Wi-Fi, параметрів кінцевика та документації API для економії місця на екрані.

## Схема підключення пінів (За замовчуванням)

Конфігурація пінів знаходиться у файлі [`include/config.h`](file:///include/config.h):

| Призначення | Пін ESP32 | Підключення до драйвера / модуля |
| :--- | :--- | :--- |
| **STEP** | `GPIO 18` | Вхід `STEP` драйвера крокового двигуна (A4988 / TMC2209 / DRV8825) |
| **DIR** | `GPIO 19` | Вхід `DIR` драйвера крокового двигуна |
| **ENABLE** | `GPIO 5` | Вхід `EN` драйвера (активний рівень LOW за замовчуванням, налаштовується у веб-інтерфейсі) |
| **ENDSTOP** | `GPIO 4` | Кінцевик: один контакт на `GPIO 4`, другий на `GND` (внутрішня підтяжка `INPUT_PULLUP`) |

> Рівні STEP, DIR і ENABLE підбираються під логіку входів драйвера в адмінці.
> Полярність сигналу не визначає схему підключення оптопари: дотримуйтеся
> рекомендацій виробника драйвера щодо common-anode/common-cathode, живлення та
> обмеження струму. Не подавайте на GPIO ESP32 напругу понад 3.3 В.

> **Примітка щодо кінцевика**: Логіку спрацьовування (інверсію) та час фільтрації брязкоту тепер можна перемикати прямо у веб-інтерфейсі в розділі «Налаштування кінцевика та столу».

## Налаштування механіки та кінематики

У файлі [`include/config.h`](file:///include/config.h) за необхідності відкоригуйте параметри приводу:

```cpp
constexpr float STEPS_PER_MOTOR_REV = 200.0f; // Кроків двигуна на 360° (200 для 1.8°, 400 для 0.9°)
constexpr float MICROSTEPS          = 16.0f;  // Мікрокрок драйвера (1, 2, 4, 8, 16, 32...)
constexpr float GEAR_RATIO          = 1.0f;   // 1.0 = прямий привід; якщо редуктор 4:1, вкажіть 4.0
```

Формула розрахунку кроків на 1 градус повороту:
$$\text{STEPS\_PER\_DEGREE} = \frac{\text{STEPS\_PER\_MOTOR\_REV} \times \text{MICROSTEPS} \times \text{GEAR\_RATIO}}{360}$$

## Документація REST Web API (JSON)

Базовий URL: `http://<ESP32_IP>` або `http://rotating-table.local`.

### 1. Калібрування нуля (Homing)
Запускає обертання вліво до кінцевика та обнуляє систему координат.

- **URL**: `/api/home`
- **Метод**: `POST`
- **Тіло запиту**: `{}`
- **Відповідь**:
  ```json
  {
    "status": "ok",
    "message": "Калібрування запущено"
  }
  ```

Приклад cURL:
```bash
curl -X POST http://rotating-table.local/api/home -H "Content-Type: application/json" -d "{}"
```

---

### 2. Поворот столу (Move)
Повертає стіл на заданий кут із вказаною швидкістю.

- **URL**: `/api/move`
- **Метод**: `POST`
- **Тіло запиту (JSON)**:
  ```json
  {
    "angle": 90.0,
    "speed": 45.0,
    "relative": false
  }
  ```
  - `angle` *(float, обов'язково)*: кут у градусах.
  - `speed` *(float, опціонально)*: швидкість у градусах на секунду (типово 30°/с, максимум 180°/с).
  - `relative` *(bool, опціонально)*: `false` — абсолютна позиція від 0°, `true` — відносний поворот на вказаний кут від поточного положення.

- **Відповідь**:
  ```json
  {
    "status": "ok",
    "message": "Команду повороту прийнято",
    "target_angle": 90.0,
    "speed": 45.0,
    "relative": false
  }
  ```

---

### 3. Опитування стану (Status)
Повертає поточні координати столу, статус калібрування та стан кінцевика.

- **URL**: `/api/status`
- **Метод**: `GET`
- **Відповідь**:
  ```json
  {
    "status": "ok",
    "state": "IDLE",
    "current_angle": 90.0,
    "target_angle": 90.0,
    "speed": 45.0,
    "is_homed": true,
    "endstop_triggered": false
  }
  ```
  Додатково відповідь містить поля `imu_pitch_deg`, `imu_roll_deg`,
  `imu_gyro_x_dps`, `imu_gyro_y_dps`, `imu_gyro_z_dps`,
  `imu_mpu6050_connected`, `imu_barometer_connected` та `imu_error`.
  Для калібрування доступні `POST /api/imu/calibrate` (датчик має бути
  нерухомим) та `POST /api/imu/zero` (поточне положення зберігається як 0°).
  Значення `state`:
  - `IDLE` — стіл нерухомий, готовий до команд.
  - `HOMING` — триває процес пошуку кінцевика.
  - `MOVING` — стіл виконує поворот.
  - `STOPPED` — аварійна зупинка.
  - `ERROR` — помилка (наприклад, таймаут кінцевика).

## Приклад керування на Python

Див. файл [`example_client.py`](file:///example_client.py):

```python
import requests
import time

BASE_URL = "http://rotating-table.local"

def home_table():
    print("Калібрування нуля...")
    requests.post(f"{BASE_URL}/api/home")
    while True:
        st = requests.get(f"{BASE_URL}/api/status").json()
        if st["state"] != "HOMING":
            print(f"Готово! Стан: {st['state']}")
            break
        time.sleep(0.5)

def rotate_to(angle, speed=45.0):
    print(f"Поворот на {angle}° зі швидкістю {speed}°/с...")
    requests.post(f"{BASE_URL}/api/move", json={
        "angle": angle,
        "speed": speed,
        "relative": False
    })
    while True:
        st = requests.get(f"{BASE_URL}/api/status").json()
        if st["state"] == "IDLE":
            print(f"Досягнуто кут: {st['current_angle']}°")
            break
        time.sleep(0.3)

if __name__ == "__main__":
    home_table()
    for deg in range(0, 360, 45):
        rotate_to(deg)
        print(f"Знімок на {deg}°...")
        time.sleep(1)
```

## Окрема збірка та прошивка через PlatformIO

У проекті налаштовано два незалежних середовища в [`platformio.ini`](file:///platformio.ini):

### 1. Прошивка поворотного столу (Основна плата / Master)
Містить Wi-Fi, HTTP веб-сервер, веб-панель керування та BLE-клієнт:
```bash
# Збірка бінарного файлу
pio run -e rotating_table

# Прошивка через USB
pio run -e rotating_table -t upload

# Монітор Serial (115200)
pio device monitor -e rotating_table
```

### 2. Прошивка платформи нахилу (Друга плата / Slave)
Містить драйвер з опторозв'язкою (керування LOW-сигналами), гіроскоп GY-521 (MPU-6050) зі стабілізацією, кінцевик крайньої точки та BLE-сервер:
```bash
# Збірка бінарного файлу
pio run -e tilt_platform

# Прошивка через USB
```

## Підключення плати нахилу (Tilt Platform)

Конфігурація пінів платформи нахилу знаходиться у файлі [`include/tilt_config.h`](file:///include/tilt_config.h) та може бути повністю переналаштована дистанційно через веб-інтерфейс:

| Призначення | Пін ESP32 | Підключення до модуля / драйвера |
| :--- | :--- | :--- |
| **STEP** | `GPIO 18` | Вхід `PUL-` драйвера крокового двигуна (активний рівень **LOW**) |
| **DIR** | `GPIO 19` | Вхід `DIR-` драйвера крокового двигуна |
| **ENABLE** | `GPIO 5` | Вхід `ENA-` драйвера крокового двигуна (активний рівень **LOW**) |
| **PUL+/DIR+/ENA+** | `+5V` або `+3.3V` | Спільний анод (Common Anode) оптичної розв'язки драйвера |
| **ENDSTOP** | `GPIO 4` | Кінцевик крайньої точки: пін `GPIO 4` та `GND` (внутрішній pull-up) |
| **I2C SDA** | `GPIO 21` | Пін `SDA` модуля **GY-521** (MPU-6050) |
| **I2C SCL** | `GPIO 22` | Пін `SCL` модуля **GY-521** (MPU-6050) |

> **Управління рівнями LOW**: Оптично ізольовані драйвери крокових двигунів (наприклад, DM542, TB6600 тощо) при схемі зі спільним анодом спрацьовують, коли катод оптопари притягується до землі (**LOW**). Прошивка платформи нахилу за замовчуванням генерує імпульси кроку та сигнал увімкнення рівнем LOW (`stepActiveLow = true`, `enableActiveHigh = false`). Полярність можна додатково змінити через веб-інтерфейс.

## Керування та налаштування з основної адмінки

Після увімкнення обох плат керування ведеться з веб-інтерфейсу основної плати (`http://rotating-table.local` або за її IP-адресою):

1. **Bluetooth зв'язок та прив'язка**:
   - Основна плата автоматично сканує та підключається до плати `TiltTable-ESP32`.
   - В адмінці у розділі «Налаштування плати нахилу» доступне сканування ефіру, вибір знайденого пристрою зі списку або введення конкретного MAC-адреси.
   - Відображається рівень сигналу RSSI та статус підключення (BLE ONLINE / OFFLINE).
2. **Живі показання та стабілізація**:
   - Показання гіроскопа **GY-521** (Pitch / Roll) та розрахований кут нахилу платформи транслюються в реальному часі кожні 300 мс.
   - Кнопка **«Підтримувати кут (Hold Mode)»**: вмикає замкнений контур регулювання. Якщо платформа відхиляється або нахиляється під навантаженням, двигун автоматично підрулює, повертаючи її до заданого кута.
3. **Ручне виставлення в нуль та скидання гіроскопа в пам'ять**:
   - Кнопка **«Стіл в 0° вручну»**: обнуляє поточну позицію крокового двигуна без фізичного руху.
   - Кнопка **«Скинути гіроскоп (Запам'ятати 0°)»**: зчитує поточне горизонтальне положення платформи по рівню, калібрує зміщення та записує його в енергонезалежну Flash-пам'ять **NVS** плати нахилу. При наступних включеннях стіл пам'ятає це горизонтальне положення!
   - Кнопка **«Калібрувати гіроскоп»**: усуває дрейф сенсора у стані спокою.
   - Кнопка **«Знайти кінцевик (Home)»**: здійснює двоетапний підхід до кінцевика крайньої точки для виставлення апаратного нуля.
4. **Дистанційне налаштування пінів та кінематики**:
   - Усі налаштування (піни STEP, DIR, ENABLE, ENDSTOP, SDA, SCL, рівні сигналів, редукція, швидкості, прискорення, коефіцієнт стабілізації Kp) змінюються в адмінці та передаються по Bluetooth на другу плату, де надійно зберігаються у Flash-пам'ять.
